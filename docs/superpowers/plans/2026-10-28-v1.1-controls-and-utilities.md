# Cardputer Modular v1.1 Implementation Plan: unified controls, reliable tilt, utility modules

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One "do it" gesture everywhere (`fn`+tap = hold = tap then `enter`), tilt sweep on hold-`enter` that tracks the device reliably, and seven new modules (MIX, ATN, S&H, CLK, MUX, DMX, TILT) from the spec's §8.2 list, then the v1.1 release.

**Architecture:** A new gesture layer (`src/ui/gesture.*`) turns raw `KeyEvent`s into `Action`s (Select, Activate, Sweep, SweepEnd, Key) in one place; every view handles `Action`s from a view table, so a later UI refactor remaps gestures without touching views. Tilt angles come from a pure, natively tested `TiltFilter` fed by the IMU on core 0, which also publishes angles to the new TILT module through atomics. New modules follow the existing `ModuleTypeInfo` + registry pattern.

**Tech Stack:** PlatformIO, Arduino core (espressif32@6.11.0), M5Unified 0.2.28, M5Cardputer 1.1.1, DaisySP (MIT core), Unity native tests.

**Spec:** `docs/superpowers/specs/2026-10-27-cardputer-modular-design.md` (v1 design), plus the owner decisions of 2026-10-28 recorded below. Branch: keep working on `feat/v1-firmware` (v1 is not merged yet).

### Root cause of "tilt doesn't work reliably" (found while planning)

`M5.Imu.getAccel()` returns `false` whenever the BMI270 has no *new* sample since the last read (`IMU_Class::update()` returns the data-ready mask; `BMI270_Class::getImuRawData` checks `INT_STATUS_1`). `src/hw/tilt.cpp` turns `false` into a roll of `0`. The UI loop polls far faster than the accelerometer's data rate, so during a sweep the value keeps snapping to "flat" and back, and the baseline captured at sweep start is often 0. A second, smaller cause: `atan2f(ax, az)` swings wildly when the device is held near vertical (az ≈ 0). Task 3 fixes both.

## Global Constraints

- PlatformIO + Arduino core; `pio` is `~/.platformio/penv/bin/pio`. Native tests: `~/.platformio/penv/bin/pio test -e native`. Device build: `~/.platformio/penv/bin/pio run -e cardputer`. Never run two builds at once (a concurrent build corrupted an ELF once).
- Delivered as a `.bin` for bmorcelli's Launcher. **No custom partitions.** Assets on SD under `/modsynth/`.
- DaisySP MIT core only, never DaisySP-LGPL.
- Every signal is audio rate: 1 V/oct, audio and bipolar CV about ±5 V (`kAudioVolts = 5`), gates high above `kGateOn = 1.0 V`, low below `kGateOff = 0.5 V`, gate outputs are `kGateHighVolts = 5 V`.
- No allocation on the audio thread; no I2C from the audio thread (the IMU is read on core 0 only).
- Module ids are stable lowercase strings and are saved in patch files: never rename one.
- Limits: `kMaxParams = 8`, `kMaxIns = 4`, `kMaxOuts = 4`, cell labels ≤ 3 chars, blurb ≤ 40 chars.
- Hold time `kHoldMs = 400`.
- Big objects are statics, never on a task stack.

### Task 1: Gesture mapper

**Files:**
- Create: `src/ui/gesture.h`, `src/ui/gesture.cpp`
- Test: `test/test_input/test_main.cpp` (add tests)

**Interfaces:**
- Consumes: `KeyEvent`, `Side`, `kHoldMs` (`src/ui/key_input.h`, `src/core/units.h`).
- Produces:

```cpp
// src/ui/gesture.h
enum class Act : uint8_t {
    Key,       // raw passthrough: side keys other than Enter, grid Up, and everything in raw mode
    Select,    // grid Down: put the cursor on `cell`
    Activate,  // "do it": cell >= 0 a grid cell, cell == -1 the current selection (from Enter)
    Sweep,     // Enter held >= kHoldMs
    SweepEnd,  // Enter released after a Sweep
};
struct Action {
    Act act;
    int8_t cell;   // row * 12 + col for Select/Activate from the grid, -1 otherwise
    KeyEvent key;  // the raw event that produced this action
};
class GestureMapper {
   public:
    // raw = true (Keys play view): every event becomes one Act::Key, no state changes except
    // forgetting pending Enter/activation state. Returns the number of actions written (<= 2).
    int map(const KeyEvent&, bool fnHeld, bool ctrlHeld, bool raw, Action* out);
    void reset();  // forget pending Enter and per-key activation state (view changes)
};
```

Mapping rules (the whole design; the implementer writes the state machine):
- Grid Down: emit `Select(cell)`; if `fnHeld`, also emit `Activate(cell)` and mark that key activated.
- Grid Hold: emit `Activate(cell)` unless that key was already activated by `fn` or `ctrlHeld` is true at the Hold.
- Grid Up: emit `Key` and clear the key's activated mark.
- Enter Down: emit nothing; remember it. Enter Hold: emit `Sweep`. Enter Up: emit `Activate(-1)` if no Sweep fired, else `SweepEnd`.
- Every other side event: `Key`.

// roll = atan2(ax, sqrt(ay*ay + az*az)), pitch = atan2(ay, sqrt(ax*ax + az*az)), in degrees.

### Module tasks (5–8): shared pattern
