# Cardputer Modular v1.2 Implementation Plan: feature complete

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (owner chose native + one persistent Opus reviewer). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the firmware feature complete: module pages, unified paged menus, a polished and animated UI that answers every key press, many more modules (including GRD, a Plaits/Grind macro oscillator), input attenuverters, more keyboard layouts, factory patches.

**Architecture:** Same layers as v1.1. Core limits grow (`kMaxParams` 16, `kMaxIns` 8). The module-view layout becomes paged (`src/ui/layout.*`): a type gets automatic pages, or declares its own (`PageDef`). One `sideIcons()` function in `src/ui/` decides every side-strip icon, so it can be tested natively. The renderer only draws it. New modules follow the `ModuleTypeInfo` + registry pattern. Big buffers come from a generalised static pool (`src/core/buffer_pool.*`, the old delay pool).

**Tech Stack:** PlatformIO, Arduino core (espressif32@6.11.0), M5Unified 0.2.28, M5Cardputer 1.1.1, DaisySP (MIT core), Plaits + stmlib (MIT, vendored into `lib/`), Unity native tests.

**Spec:** `docs/superpowers/specs/2026-10-27-cardputer-modular-design.md`, plus the owner requests of 2026-10-28 (session 3) below. Branch: keep `feat/v1-firmware`. The v1.1 Task 9 checkpoint and Task 10 fold into Task 14 here.

### Calls made for this plan [Claude's call]

- Module-view `tab` stops being "next parameter" and becomes "next page" (owner suggested). Cursor moves by tap anyway.
- On a `Bit` cell (sequencer steps), a plain tap toggles. It's an exception to "tap selects", like the number row, because a step grid is played by tapping.
- Chord = a grid Down while another grid key is still held and not yet activated. The held key's hold timer is then cancelled.
- Patch view chord: held module → empty cell = move; → occupied cell = swap. Module view chord: held pin → pin of the opposite kind = patch the cable directly.
- Copy: while a move is pending, `fn`+target cell places a copy (params and amounts, no cables). The `fn` icon shows Copy then.
- Redo = `fn`+`\`. Undo/redo share one ring (cursor), so RAM is unchanged.
- `fn` held ≥ 600 ms with no other key shows a help overlay naming the 8 side-key actions of the current view.
- Categories become Source, Modulator, Processor, Effect, Utility. The place menu has one page per category (36 tiles each).
- USB MIDI host stays deferred: it needs the owner's powered OTG adapter to verify, and host mode drops the USB serial console. Not in this plan.

## Global Constraints

- PlatformIO + Arduino core; `pio` is `~/.platformio/penv/bin/pio`. Native tests: `~/.platformio/penv/bin/pio test -e native`. Device build: `~/.platformio/penv/bin/pio run -e cardputer`. Never run two builds at once.
- Delivered as a `.bin` for bmorcelli's Launcher. **No custom partitions.** Assets on SD under `/modsynth/`.
- DaisySP MIT core only, never DaisySP-LGPL (no ReverbSc). Plaits/stmlib are MIT.
- Signals: 1 V/oct, audio and bipolar CV ±5 V (`kAudioVolts`), gates high above `kGateOn = 1.0 V`, low below `kGateOff = 0.5 V`, gate outputs `kGateHighVolts = 5 V`.
- No allocation on the audio thread; no I2C from the audio thread.
- Module ids and param/pin keys are stable lowercase strings saved in patch files: never rename one. Old patches must load unchanged (stepped params that gain options keep old values meaning the same).
- Limits after Task 1: `kMaxParams = 16`, `kMaxIns = 8`, `kMaxOuts = 4`, cell labels ≤ 3 chars, blurb ≤ 32 chars, `sizeof(Patch) <= 4608`.
- Big objects are statics, never on a task stack.

```cpp
// units.h
kMaxParams = 16, kMaxIns = 8;               // kMaxOuts stays 4
// module.h
void Module::setInAmount(int i, float a);  float Module::inAmount(int i) const;  // default 1
float Module::peak() const;                 // engine-written |out(0)| peak of the last block
// patch.h
struct ModuleRec { ...; float inAmount[kMaxIns]; };     // addModule sets all to 1
PatchError Patch::copyModule(uint16_t id, uint8_t page, uint8_t cell, uint16_t* outId);  // no cables

// undo.h
class UndoStack { void push(const Patch& before, uint32_t key=0); bool undo(Patch& cur); bool redo(Patch& cur);

Patch JSON: `"inamounts": {"pitch": 0.5, ...}` per module (only keys present are read; absent = 1). Keep `kFormat = 1` (older firmware ignores the new key).
