# Cardputer Modular v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A flashable `.bin` for the Cardputer-Adv that lets the owner build, play, save and load the
v1 modular patch (KEYS, OSC, VCF, VCA, ENV, LFO, DLY, OUT) on the device's 12×4 key grid, and
sample it into a PO-33.

**Architecture:** Everything that isn't hardware lives in `src/core/` (DSP modules, patch model, engine,
undo, patch files) and `src/ui/` (input decoding and the view state machine). Both are plain C++17 and are
unit-tested on the Mac with `pio test -e native`. `src/hw/` (I2S/ES8311, keyboard, SD, tilt) and `src/render/`
(M5GFX drawing) are thin and device-only. Core 1 runs only the audio task, which calls
`Engine::processBlock`. Core 0 runs the UI task: keys → `UiController` → `Patch` + `Engine::apply` → render.
The UI thread compiles a new `Program` (module order + input wiring) and publishes it with an atomic pointer.
Audio picks it up at the next block boundary. Module instances outlive programs, so oscillator phase and
delay memory survive edits.

**Tech Stack:** PlatformIO 6.2 (`~/.platformio/penv/bin/pio`), platform `espressif32@6.11.0` (Arduino-ESP32
2.0.17 / ESP-IDF 4.4, already installed), board `m5stack-stamps3`, M5Unified 0.2.28, M5GFX ≥0.2.35,
M5Cardputer 1.2.0, ArduinoJson 7, DaisySP MIT core vendored at commit `2c72eaf`, Unity for native tests.

**Spec:** `docs/superpowers/specs/2026-10-27-cardputer-modular-design.md` (approved 2026-10-27).
Hardware facts: `docs/hardware-spec.md`. Look: `docs/design/` (`01`–`05` PNGs, `mockups.html`).

## Global Constraints

- Delivery: the standard `firmware.bin` from `pio run -e cardputer`, run from bmorcelli's Launcher. **No custom partition table** (keep the board default). Large assets go on SD under `/modsynth/`.
- DSP library: DaisySP **MIT core only**. Never copy or add the `DaisySP-LGPL` submodule (e.g. ReverbSc, Port).
- Audio: 48 000 Hz, block size `kBlock = 32`, mono float. Output path: I2S stereo 16-bit Philips, both channels carry the same sample.
- Signal units: `1.0f` = 1 V. Pitch 1 V/oct with 0 V = C4 = 261.6256 Hz. Audio and bipolar CV ±5 V. Unipolar CV (ENV) 0…+5 V. Gate high = 5 V. A gate reads high at > 1.0 V and low again at < 0.5 V.
- Signal rules: every signal is audio rate. Inputs sum. Outputs fan out. Every output has an amount −1…+1, applied when it is summed into an input. Feedback loops are allowed; the cable that closes a loop reads the previous block.
- Audio thread (core 1): no heap allocation, no locks, no I2C, no logging, no `double`. Only `float` math (`f` suffixes; `-Wdouble-promotion` is on for `src/core`).
- I2C (keyboard, codec, IMU) is used only from core 0.
- Patch files: JSON in `/modsynth/patches/`, field `"format": 1`. Module type ids, parameter keys and pin keys are **stable lowercase strings**. Never rename them: old patches must keep loading.
- Style B palette (spec §6): background `#c4c6b8`, side strips `#b6b8aa`, text `#1d1f1a`, dim `#5e6157`, faint `#9a9d90`, cell border `#8f9286` (1 px dotted), accent `#ff4d1a`, empty value segment `#adb0a2`, category bar `#1d1f1a`. Cable colours in order: `#ffe14d` `#ff8fc8` `#39d0ff` `#ff3d9a` `#a77bff` `#b6ff3b`.
- Map keys by **physical position**, not legend (spec §5). Grid rows in code are 0-based: row 0 = number row (`1`…`=`), row 1 = `q` row, row 2 = `a` row, row 3 = `z` row. Cell index = row·12 + col.
- Commit after every task, with messages ending in `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Bad patch files on SD** (truncated JSON, unknown types, parameters out of range, cables to missing modules or bad pin names, two modules in one cell, a `format` newer than 1): the load is refused or cleaned up, never crashes, and the current patch is unchanged if parsing fails. Tests in Task 12.
2. **SD missing, removed or full** during save, load or autosave: show the toast `NO SD` / `SAVE FAILED` and keep playing. Tests in Task 17.
3. **Runaway feedback** (an OSC FM-ing itself at +100%, DLY output into its own input, VCF at max res and drive): the output stays finite and bounded. A NaN anywhere must not lock the output into silence for good. Tests in Task 10.
4. **Edits that remove what the UI is pointing at** (delete or undo away the module you're carrying a cable from, or the one whose view is open; load a patch while carrying): the carry is cancelled, the view falls back to the patch view, no dangling ids. Tests in Task 16.
5. **Running out of resources** (33rd module, 65th cable, a third DLY, a second OUT or KEYS, loading a patch bigger than the RAM): refused with a clear toast, nothing half-created. Tests in Tasks 9, 10, 12.

  Each module file exports `extern const ModuleTypeInfo kOscType;` etc. Adding a module means one file plus one line in `registry.cpp`.
- OSC `"osc"` OSC, Source, Icon Osc. Params:

  | key | label | range | default | curve |
  |---|---|---|---|---|
  | `wave` | WAV | 0–3: SIN/TRI/SAW/SQR | SAW | Stepped |
  | `oct` | OCT | −4…+4 | 0 | Stepped |
  | `tune` | TUN | −12…+12 semitones | 0 | Lin |
  | `fine` | FIN | −100…+100 cents | 0 | Lin |

  Ins `pitch` PIT, `fm` FM. Out `out` OUT. Freq = `voltsToHz(oct + tune/12 + fine/1200 + pitch + fm)`, clamped to 0.1…20 000 Hz. Output ±5 V. Use the DaisySP `Oscillator` polyblep waves (`WAVE_SIN`, `WAVE_POLYBLEP_TRI`, `WAVE_POLYBLEP_SAW`, `WAVE_POLYBLEP_SQUARE`). Monitor 0 = current frequency.
- VCA `"vca"` VCA, Processor. Param `level` LVL 0…1, default 1, Lin. Ins `in` IN, `cv` CV. Out `out`. Output = `in·level·(cv connected ? clamp(cv/5, 0, 1) : 1)`, with the gain slewed over 2 ms.

    explicit Engine(HeapFreeFn heapFree);            // native tests pass a lambda returning a large value
    Refusal canAdd(const Patch&, const ModuleTypeInfo&) const;  // cpu: Σ cpuCycles + t.cpuCycles ≤ kCpuBudget (4000);
                                                                // ram: heapFree() ≥ t.ramBytes + 24 KB; dly: delayPoolFree() > 0

                                                     // push every param + amount, compile, publish. Returns # modules not instantiated.

    void setOutAmount(uint16_t id, uint8_t o, float a);

  };

Feedback works with no special code because outputs persist between blocks.

Removed modules and old programs go on a retire list tagged with the generation that dropped them. `collect()` frees the entries whose generation ≤ `seen_`. Nothing ever waits.

Then call `process`, and sum all `masterOut()` blocks into `mono`. **NaN guard:** apply `sanitize` to each module's output buffers after `process`, so one blown-up module can't poison the graph.
